The Three Extraction Paradigms

Architectural philosophy, trade-offs, and operational mechanisms.

Method 1

Rule-Based Heuristic

Deterministic regex grammar and punctuation-splitting baseline. Operates entirely offline without API calls.

  • ✓ Zero API Cost & Instant Execution
  • ✓ 100% Quote Faithfulness
  • ✗ High semantic noise (abbreviations, headers)
  • ✗ Cannot understand context (Intro vs Mind)
  • ✗ 61.5% Recall on gold clinical keynotes
Method 2

Pure Groq LLM (120B)

Direct zero-shot prompting of openai/gpt-oss-120b directly from raw section chunks.

  • ✓ High Clinical Comprehension (80.8% Recall)
  • ✓ Nuanced understanding of 19th-century English
  • ✗ 24 Chunk Failures (schema validation errors)
  • ✗ Expensive token consumption from scratch
  • ! Occasional ungrounded paraphrasing
Method 3 · Recommended

Hybrid Neuro-Symbolic

Two-stage pipeline: Symbolic candidate extraction grounded in source text + Groq 120B semantic audit and reclassification.

  • ✓ 80.8% Keynote Recall with 0 Failures
  • ✓ Prunes Non-Symptom Noise ('St', 'Common Salt')
  • ✓ Semantic Disambiguation (Grief $\rightarrow$ Affective)
  • ✓ Guaranteed Fallback (Never crashes batch)
  • ✓ 100% Verbatim Quote Preservation

Heuristic Derivation of Modalities & Cognitive Domains

The exact syntactic and ontology mapping mechanisms used in the graph.

⚡ Modality Extraction Logic

In homeopathy, modalities explain what makes a symptom or patient worse (Aggravation) or better (Amelioration).

  • Section-Level Modalities: In the Modalities section, lines starting with "Worse", "<", or "agg." are mapped to AGGRAVATED BY. Lines with "Better", ">", or "amel." map to AMELIORATED BY.
  • Clause-Level Factors: _parse_modality_factors() splits on . Better and commas, isolating clean factor labels (e.g. "Cold drinks", "Warmth", "After midnight").
  • Symptom-Level Modalities: Extracted directly from within symptom sentences containing inline qualifiers (e.g. "headache < motion").

🧠 Cognitive Domain Mapping

To support downstream affective/neuropsychiatric research, mental symptoms are linked to 6 standardized cognitive domains via MAPS TO edges:

Context Chunking & K-RAG Storage Architecture

Why section-level chunking and hybrid Neo4j + ChromaDB indexing are mathematically optimal.

📐 Remedy × Section Chunking

Chunks are scoped strictly to Remedy × Section (e.g. Aconitum napellus | Mind):

  • Optimal Context Window: Average length is 300–1,500 characters (~75–350 tokens). Eliminates context saturation and "lost-in-the-middle" LLM attention degradation.
  • Zero Cross-Contamination: Gastric symptoms never contaminate mental symptoms because section boundaries are respected.
  • Safe Sentence Splitting: If any single section exceeds 2,000 characters, it is cleanly split along paragraph boundaries without cutting clinical clauses in half.

🗄️ Neo4j vs ChromaDB (The Division of Labor)

Neither a vector database nor a graph database alone can solve this task:

  • ChromaDB + BGE Embeddings (Semantic Vector Index): Acts as the fuzzy natural language entrypoint. Understands that modern queries (e.g. "crying spells, feeling heartbroken") match archaic literature ("silent grief, weeping, melancholia").
  • Neo4j (Relational Property Graph): Executes multi-hop graph traversals, connects modalities ("aggravated by cold"), computes repertory coverage scores, and tracks provenance back to exact page numbers.
