MPCS · Progress Report · Experimental track

From Feature Counting to Grounded Recall

How eight generations of the MPCS memory were built, measured, and improved — from a two-sense counter to a hybrid filter with an explanation head.
Status as of 28 Sep 2026 Code: Model/experimental/01–07, comparison/ Companion: Perceptual Memory Indexing gameplan
Summary

MPCS decides what to do with a percept by recalling similar past experiences and the rewards they earned. The original models counted matching features, used a Bloom filter to decide whether to look at memory at all, and supported two senses and four actions. On today's 700-memory bank they pick the right action 38–43% of the time and choose an unsafe action on 41–62% of queries.

We implemented the three ideas in the gameplan one at a time — HyST (hard/soft filtering), HMGI (modality-partitioned indexing) and KERL (graph-conditioned reading) — plus SHMF, our combination of the first two. Each was measured against every earlier model on every memory bank with one harness. The current models reach 75.6% accuracy on fresh scenes and 68.1% with sensor noise, with 1.7–3.8% unsafe decisions.

The biggest single gain came from HyST's hard filter. The Bloom-filter gate never improved a decision. HMGI reduced scanning but not latency. KERL now adds interpretability more than accuracy.

01

The problem, from scratch

An agent perceives a scene — something it sees, hears, touches and smells — and must choose one of a few actions: approach, observe, alert, ignore or withdraw. It has no rulebook for most scenes. What it has is memory: every past scene, the action taken, and the reward that followed.

The core idea of MPCS (case-based reasoning) is simple: find past scenes like this one and do what worked there. Almost everything in this report is about making the two halves of that sentence precise:

  • "Like this one" — which features must match, which may differ, and how much each difference should cost.
  • "What worked there" — how to combine several memories that disagree, and what to do when no memory applies.

Speed matters too: memory grows every step, so scanning all of it on every percept eventually becomes the bottleneck. That is where indexing comes in.

Why this is hard

A hot pan and a cool pan look identical. If similarity is "count matching features", they are 3/4 the same, and the pan you were rewarded for picking up yesterday votes for picking up this one. Some features are not just features — they decide whether the rest of the comparison matters at all.

02

Building blocks: percepts, memories, similarity

Percept

A percept is a dictionary of senses, each a dictionary of discrete features:

vision: {color: red, shape: round, motion: still} audio: {sound_type: hiss, audio_intensity: medium} touch: {temperature: hot, texture: smooth} smell: {odor: burnt}

Senses may be missing — a scene in the dark has no vision. Handling partial percepts turned out to matter a great deal (§9).

Memory entry

Each memory stores the percept's summary, the action taken, the reward (−1 to +1), the step at which it happened (for ageing), and flags such as is_expert for corrections supplied by a teacher.

Z-numbers: value plus confidence

A Z-number pairs a value with how sure we are of it: (hot, 0.9). Every feature in a summary is stored as (key, value, confidence), with confidence set per sense (e.g. touch is trusted more than smell). This lets similarity discount features we barely perceived.

# similarity of query q to memory m (after the Sept fix) sim(q, m) = Σmatching features min(cq, cm) / Σfeatures of q cq

An exact repeat scores 1.0; a scene sharing nothing scores 0. The earlier product form cq·cm capped exact repeats at ~0.96 (§11).

From similar memories to a decision

For each action, retrieve the most similar memories where that action was taken, then combine their rewards weighted by similarity and age. The action with the best supported value wins. Novelty — one minus the best similarity — tells the agent how unfamiliar the scene is, and drives exploration.

Reflexes

A few hard-coded rules (a loud alarm → alert, a hot surface → withdraw) fire before memory is consulted. They matter again in §5: they tell us which features are safety-critical.

03

The legacy line: Basic, Bloom, Z-numbers

G1 · reference/mpcs.py
Basic
Vision + audio, four actions. Similarity = number of equal features. Global top-5 recall, reward-weighted vote.
G2 · reference/BloomMPCS.py
Bloom gate
A Bloom filter answers "have I seen exactly this before?". Memory is only consulted if the answer is yes — intended as a speed-up.
G3 · 01_baseline_z/MPCS_Z.py
Z-numbers + dlCBF
Z-number summaries and a d-left counting Bloom filter (supports deletion as memories age out). Confidence fixed at 1.0.

Where the idea came from. Bloom filters are the textbook structure for cheap set-membership tests; d-left counting Bloom filters (Bonomi et al.) extend them to deletions with less memory. Z-numbers come from Zadeh's (2011) proposal to attach reliability to fuzzy values.

What the measurements showed

  • The gate never helps a decision. When it opens, G2/G3 return exactly G1's decision (100% agreement on every seen set). When it closes, nothing is retrieved and the model rolls a random prior. On v1 near queries, accuracy falls from 45.7% to 31.2%.
  • Similarity needs near matches, a membership filter only knows exact ones. Case-based reasoning is valuable precisely on scenes not seen verbatim — the ones the gate shuts out.
  • Collisions look like recognition. On v2, once touch and smell are projected away, 44% of new scenes exactly match a stored one. The gate reports "seen" for scenes that differ in heat or smell.
  • Z at confidence 1.0 is just counting. G3's outputs equal G2's everywhere; Z-numbers only pay off once confidences differ.
04

Core v2: four senses and confidence

02_core/mpcs_engine.py is the shared engine every later model builds on. It adds touch and smell, the withdraw action, per-sense confidence, reflexes, a working-memory state, ageing, expert memories, and exploration. The dlCBF survives only as an exact-repeat hint, not a gate. Tkinter, Plotly, Streamlit and web dashboards (03_dashboards) visualise it.

A regression we had to explain

Core v2 scores below Basic (24.1% vs 51.7% on v1 seen; 34.2% vs 43.1% on v3 fresh scenes). It retrieves the top-5 memories per action and averages their rewards. An average does not care how similar its five members are, so a high-reward action backed by five loosely related memories can outvote the exact match. More senses gave the model more ways to find loosely related memories.

This diagnosis set up the next step: the problem is not the kernel, it is who is allowed to vote.

05

HyST: hard filters, soft residual

HyST

Hybrid Structured–Textual retrieval

Idea source: hybrid retrieval that splits a query into strict structured constraints and fuzzy residual (paper A of the gameplan). adapted
Some features must match exactly; the rest are ranked softly.

How it works. Features are split into hard slots and soft slots. The hard slots are derived automatically from the reflex rules — if a reflex tests a feature, that feature is safety-critical. A memory is only eligible if every hard slot agrees with the query. Among eligible memories, a graded ordinal kernel scores the soft slots (medium is closer to high than low is).

# HyST retrieval eligible = { m : m.hard == q.hard } # safety features must agree score(m) = Σ soft_kernel(q.f, m.f) · min(cq, cm) / Σ cq SlotPolicy(divergent=False, urgent=False, divergent_mismatch_discount=0.6)
  • Divergent switch (exploration). Hard mismatches are no longer excluded; they are discounted by 0.6. The agent can reason by analogy across safety boundaries when it chooses to. The 0.6 value came from a sweep.
  • Urgent flag (convergent only). Overrides divergence: strict filtering, no exploration. Under pressure, reason only from directly relevant experience.

Result. The largest step in the whole project: accuracy on hand-written banks rose from ~40% to 79–100%, and on 700-memory v3 fresh scenes from 34.2% to 64.0%, with unsafe decisions at 1.2%. Cost: on fresh or noisy scenes the strict filter often leaves nobody eligible (18% clean, 41% noisy). The model then observes — safe but uninformed.

06

HMGI: partitioned memory

HMGI

Hybrid Multimodal Graph Index

Idea source: partitioned multimodal indexing with graph links between items (paper B of the gameplan). We built the structural part only, plus instrumentation; no approximate-nearest-neighbour index. adapted
Index memories by which senses they carry, and link them into episodes.
  • PartitionedMemory — memories are bucketed by modality. A query only scans memories that share at least one sense with it.
  • Episode graph edges — each memory links to the previous step, the previous time the same action was taken, and the previous time the same object was seen. KERL later uses these.
  • ScanInstrumentation — records how many memories each query touches.

Result. Decisions identical to Core v2 by construction (100% agreement). Scanning drops from 700 to ~637–671 memories per query, but latency does not improve (equal to ~25% slower): building the candidate list costs about what it saves at this size. HMGI's value is structural — the partitions and graph that SHMF and KERL rest on — and it will pay off in speed only once memory is much larger.

07

SHMF: the hybrid

SHMF

Smart Hybrid-Modality Filtering

Our combination of HMGI and HyST. ours
Partition first, then filter hard/soft — and relax when the filter leaves nothing.

Partition

HMGI narrows memory to modality-compatible entries.

Strict filter

HyST's hard slots remove safety-incompatible entries. Novelty is always measured on this strict set, so the agent still knows the scene is unfamiliar.

Auto-relax

If nothing survives, retry in divergent mode (discounted hard mismatches, zero-similarity entries dropped). Never under the urgent flag.

Score and decide

Soft-kernel scoring, best evidenced action; results cached per query so one step does one scan.

Result. Auto-relax cuts empty results from 18%/41% to 2%/5% (clean/noisy) and lifts accuracy to 75.6% / 68.1% with 2.1% / 3.8% unsafe. It fixes HyST's main weakness while keeping its safety.

08

KERL: grounded, explainable reading

KERL

Knowledge-Enhanced Retrieval & Learning

Idea source: reading a retrieved subgraph with several task heads rather than one score (paper C of the gameplan). adapted
SHMF's candidates, re-read through the episode graph, with affect and an explanation.
# fused relevance, weights modulated by novelty R = w_s·sim_structural + w_e·sim_emotional + w_g·graph_2hop w_s=0.7 w_e=0.15 w_g=0.3
  • Near-miss guard — memories that the strict filter rejected by a single feature are checked, so a useful near neighbour is not silently lost.
  • HEAD-A (action value), HEAD-E (valence/arousal; when enabled, threat suppresses exploration), HEAD-X (a plain-language explanation naming the memories used).
  • UNGROUNDED — if no evidence exists, KERL says so explicitly and observes.
  • Calibration — near-miss pairs train a small pairwise perceptron over the fusion weights; a new weight set is accepted only if it strictly improves.

Result. 75.0% / 67.7% accuracy with 1.7% / 3.8% unsafe — level with SHMF. Its earlier safety lead came from observing on empty evidence; once we moved that behaviour into the shared engine (§11), every modern model got it. KERL's distinct contribution is now interpretability and adaptivity, not raw accuracy.

Bugs the benchmark found

Running every model side by side exposed two defects in the shared engine that no single-model smoke test had caught. Both were fixed in 02_core/mpcs_engine.py and propagated to HyST, HMGI and SHMF.

Fix 1
Similarity kernel
Matched features scored c1 × c2 but were normalised by Σ c1, so an exact repeat scored 0.96, not 1. Now min(c1, c2).
Fix 2
Empty-evidence decisions
With nothing retrieved, every action held a default 0.5 and max() broke the tie toward ignore — including next to a hot surface. Now best_evidenced_action chooses among supported actions and observes otherwise.

12

Where we are, and next steps

Current state

  • Eight generations implemented, each in a numbered folder with a smoke suite and a Tkinter dashboard (04_hyst → 07_kerl). All five smoke suites pass.
  • SHMF and KERL are the best models: ~75% accuracy on fresh scenes, ~68% under noise, ≤ 4% unsafe.
  • A reproducible comparison covers every model on every bank.

What we learned

  • Deciding who may vote beats tuning how votes are counted. HyST's hard filter was worth more than every kernel change combined.
  • Exact-membership structures do not fit similarity-based recall. The Bloom gates only removed evidence.
  • Safety comes from knowing when you don't know. Most of the unsafe-rate drop came from observing when nothing applies.

Recommended next steps

Close the noisy gap

68% under noise vs 76% clean. Try per-feature noise-aware confidence and letting KERL's near-miss guard feed the relaxed set.

Full-loop evaluation

The comparison scores memory recommendations only. Run closed-loop episodes with reflexes, exploration and learning on, and measure cumulative reward and time-to-safe-behaviour.

Scale test for HMGI

Generate 10k–100k memory banks to find where partitioning (and optionally an ANN index) starts to pay for itself in latency.

Measure KERL's own value

Evaluate HEAD-X explanations and HEAD-E affect directly, and test whether calibration improves accuracy over time on a drifting stream.

Stronger labels

Replace synthetic labels with a small hand-verified test set, so accuracy reflects correctness rather than agreement with the generator.
