MPCS · Technical Integration Report

Indexing Experience

A hybrid memory representation, screening and retrieval architecture for the Malleable Perceptual-Cognitive System, synthesised from HMGI, HyST and KERL.

Malleable Perceptual-Cognitive System Memory Indexing & Retrieval Track September 2026
Abstract

MPCS currently stores every experience as a flat list of confidence-weighted symbolic summaries and retrieves by linear scan with an exact-match similarity kernel. That design is correct, legible, and about to stop scaling: retrieval cost grows with the number of memories, the similarity kernel cannot express "nearly the same", and the retrieved record carries no separation between what was hard fact about a situation and what was felt about it. A d-left counting Bloom filter sits in front of the store, but experiments confirmed it buys almost nothing — it answers "have I seen this exact summary before?", and perceptual experience is almost never bit-identical twice.

This report reads three recent systems papers not as literature but as parts. HMGI supplies modality-partitioned indexing and a fused graph-plus-vector score — the fix for the flat store and for the screening layer that Bloom filters failed to provide. HyST supplies the decomposition of a query into hard structured filters and a soft semantic residual — the fix for a similarity kernel that currently treats "thermal is hot" and "colour is blue" as equally negotiable. KERL supplies subgraph-conditioned generation with task-specific adapters — the fix for retrieval that returns records but no interpretation, and no route for emotional or nutritive-style derived attributes.

We then build one architecture from the three, in five clearly separated layers, and walk a single stimulus through it end to end. Every claim is marked as paper-supported, adapted, or our own proposal.

SECTION 01

Where MPCS memory stands

The engine binds four modalities — vision, audio, touch and smell — into an AfferentObject whose summary is a tuple of (feature, value, confidence) triples, any subset of which may be absent. Similarity between two summaries is a confidence-weighted count of exactly-matching feature values, normalised by total confidence:

# Model/experimental/core/mcps_engine.py — current kernel sim_z(s₁, s₂) = Σₖ [ v₁ₖ == v₂ₖ ] · min(c₁ₖ, c₂ₖ) norm_sim = sim_z(s₁, s₂) / Σₖ c₁ₖ novelty(s) = 1 − maxₘ∈memory norm_sim(s, m.summary) # full linear scan retrieve(s, k) = top-k of memory sorted by sim_z # full linear scan again

Three properties of this kernel matter for everything that follows.

Property 1
Everything is negotiable
A mismatch on thermal costs exactly what a mismatch on color costs. Safety-critical features have no privileged status in retrieval, only later in the reflex rules.
Property 2
Nothing is graded
warm vs hot scores identically to cold vs hot — zero. The kernel has no notion of a value being close, so genuinely similar percepts read as unrelated.
Property 3
Every query touches every memory
Novelty and retrieval are two independent O(N·d) scans per cognitive step. At a few hundred records this is invisible; at 10⁵ episodes with per-step interaction it is the loop's cost centre.

Why the Bloom filter did not help

The DLeftCountingBloomFilter in the engine (4 sub-tables × 1024 buckets × 16-bit fingerprints) answers one question in O(1): has this exact summary key been inserted before? Benchmarking showed no meaningful speedup, and the reason is structural rather than an implementation defect.

Figure 1 — Why exact-membership screening cannot prune a perceptual workload
A Bloom filter is a set structure over an exact key space. Perceptual summaries live in a continuous-ish space where the same situation almost never produces an identical key, so membership queries miss and no work is saved. The right structure for this workload is not a cheaper exact test but a similarity-sensitive screen that returns a candidate neighbourhood.
The lesson we carry forward

The Bloom experiment was not a failed optimisation; it was a diagnosis. It established that MPCS does not have a membership problem, it has a neighbourhood problem. Every architectural decision in this report follows from that. Where the report proposes a fast screening layer, it is a partitioned approximate-neighbour index, not a set filter — and the dlCBF stays only in the narrow role it is actually good at: deduplicating literally-repeated preset and expert-taught entries at write time.

SECTION 02

The five questions, stated separately

The driving question — how can a perceptual system represent rich multisensory experience, efficiently judge familiarity, and retrieve what is relevant? — is really five questions that a single similarity scan is currently answering all at once, badly. Naming them separately is what lets three unrelated papers each solve one.

Figure 2 — The five separable concerns and the paper that addresses each
Concerns A–E are answered today by a single function, similarity_z, plus a linear scan. The rest of this report keeps them apart on purpose: each has a different cost profile, a different failure mode, and a different right answer.
SECTION 03

HMGI — partitioned hybrid indexing

HMGI

The Hybrid Multimodal Graph Index: A Comprehensive Framework for Integrated Relational and Vector Search

Chandra, Navneet & Zhang · arXiv:2510.10123 · 2025
Store entities as graph nodes whose embeddings are node properties, partition those embeddings by modality into separate ANN indexes, and fuse a vector score with a graph-traversal score into one ranking — with an MVCC delta store so writes never trigger an index rebuild.

Core mechanism

HMGI's argument is that vector databases and graph databases each hold half of what a multimodal query needs, and that maintaining both separately costs more in synchronisation than it saves. Its answer has three moving parts, and all three matter to us.

Modality-aware partitioning. Rather than one monolithic HNSW graph over all embeddings, HMGI fits K-means centroids per modality and builds a separate index per partition, assigning each vector by arg min_c ‖e − μ_c‖². A query that concerns one modality searches only that partition. The paper reports this reduces the searched space by up to 70%, and its own ablation shows removing partitioning raises latency from 12 ms to 17.4 ms while dropping cross-modal recall 18%.

Fused scoring. A candidate's final score combines its vector distance with the evidence gathered by traversing h hops of graph structure around it:

# HMGI, Eq. 3 — fused hybrid score S = wᵥ · (1 − dᵥ) + wg · (1/h) Σᵢ₌₁..h sgᵢ
dv normalised vector distance in [0,1] · sgᵢ score contributed by hop i of the graph traversal · wv, wg weights that HMGI adjusts dynamically per query (its DEG-inspired component) rather than fixing at build time. The important structural fact: vector proximity and relational context are summed, not chained — neither can veto the other, they trade off.

Adaptive updates. An MVCC delta store absorbs inserts; queries run ANN over the stable index and brute-force over the (tiny) delta, then merge. Asynchronous vacuuming folds the delta in later. The ablation is the persuasive part: remove the delta store and update latency goes from 50 ms to 250 ms with 15% query downtime, because every write forces a partial rebuild.

Figure 3 — HMGI mechanism, redrawn against an MPCS percept
HMGI's three components map onto MPCS almost one-to-one: modality partitions correspond to the engine's existing MODALITIES registry, the graph is the episode/object/action structure the dashboards already draw via build_graph, and the delta store is what makes an index survive a system that writes a memory on every single step.

Concretely, on our data

Suppose 40 000 stored episodes. Today, compute_novelty plus retrieve means two passes over all 40 000, each comparing ~12 feature slots — roughly 10⁶ comparisons per cognitive step. Under HMGI-style partitioning, a percept whose active modalities are touch and smell probes only those two partitions, and within them an HNSW-style graph search visits O(log N) nodes rather than N. The candidate set handed to the next stage is ~100 episodes, not 40 000.

Which MPCS problem this solves

Concerns A and B. It gives the representation layer somewhere to put structure that a flat tuple cannot hold — an episode node with typed edges to the object it involved, the action taken, and neighbouring episodes — and it gives the screening layer the thing Bloom filters could not: a sub-linear route from 40 000 memories to a candidate neighbourhood, using similarity rather than identity. The MVCC delta store is what makes this compatible with concern E, since MPCS writes a memory every step and a rebuild-on-write index would be unusable.

What it does not solve

  • Fusion is a weighted sum, so a hard constraint can always be outvoted by strong vector similarity. HMGI's own ablation notes hybrid recall drops to 85% precisely when vector proximity and relational constraints disagree.
  • It assumes learned embeddings exist per modality. MPCS features are categorical; we must design that encoder ourselves (§7).
  • Reported numbers come from billion-scale benchmarks with GPU clusters. At 10⁴–10⁵ episodes on a laptop, partition overhead could exceed the saving — this is a claim to verify, not inherit.
SECTION 04

HyST — hard filters, soft residual

HyST

HyST: LLM-Powered Hybrid Retrieval over Semi-Structured Tabular Data

Myung, Park & Han · PrompTart Lab, MODULABS · arXiv:2508.18048 · EARL '25
Split a query into (1) explicit structured constraints, executed as metadata filters inside the vector database, and (2) the unstructured residual — the subjective part — which drives dense similarity search over only the surviving candidates.

Core mechanism

HyST's target is the failure of linearisation. If you flatten {category: Italian, location: New York, review: "cozy atmosphere"} into one string and embed the whole thing, the embedding cannot distinguish a requirement from a preference. Ask for an Italian restaurant and you get a French one that is semantically adjacent — the paper's Table 4 shows exactly this: query says Spyder brand, semantic-only retrieval returns 3Skull.

The fix is a three-stage pipeline: an LLM extracts structured filter conditions in a database-native operator format ($eq, $in, $lt, $between); the query is refined to strip out what the filter now covers, leaving the semantic residual; the vector DB applies the filter first and runs similarity only over the survivors.

Figure 4 — HyST decomposition, and the MPCS analogue
The translation is direct: HyST's "explicit constraint vs subjective preference" is our "safety-critical feature vs descriptive feature". Both are cases where averaging the two into one similarity number destroys the distinction that matters.

Why this is the sharpest fix for our similarity kernel

Consider a concrete pathology in the current system. A percept arrives with thermal=hot, contact=firm, texture=rough, color=dark, motion=static. A stored memory has thermal=neutral, contact=firm, texture=rough, color=dark, motion=static — four of five features match. Normalised similarity ≈ 0.83, so novelty ≈ 0.17: the system judges this situation thoroughly familiar and retrieves an episode whose reward history says approach. The one feature that differed is the one that burns.

Under a HyST decomposition the hard predicate thermal ∈ {hot} is applied first. The comfortable memory is not down-weighted; it is not a candidate at all. Novelty is then computed over the surviving set, and if that set is empty, novelty is 1.0 and the system correctly treats the situation as unprecedented.

# Proposed — HyST-style two-part matching for MPCS C = { m ∈ Memory : Φ(m) ⊨ hard(p) } # hard predicate, index-executed sim(p, m) = Σₖ∈soft ωₖ · κ(vₚₖ, vₘₖ) · min(cₚₖ, cₘₖ) # graded kernel κ, soft slots only novelty(p) = 1 − maxₘ∈C sim(p, m) # =1.0 when C is empty — correctly unprecedented
hard(p) the predicate derived from safety-critical slots of the percept · Φ(m) the stored episode's structured attributes · κ a graded value kernel, so warm↔hot scores above cold↔hot instead of both scoring zero · ωk per-slot learned weight. Note the two departures from HyST: it uses an LLM to extract filters from free text (we read them from typed slots, no LLM needed) and it uses an ungraded metadata match (we add κ because our values are ordinal).
Which MPCS problem this solves

Concern C, and part of A. It makes novelty detection constraint-aware: the system can no longer be talked out of alarm by four irrelevant matching features. It also tells us how to lay out an episode record — the split between filterable structured metadata and embedded soft content is a storage decision, made once at write time, not a query-time trick.

What it does not solve, and one honest caution

  • HyST's own ablation (Table 3) is a warning: removing query refinement improved P@5 (0.8586 vs 0.8349) and P@10, because stripping the "soft" text discarded cues that were genuinely informative. Their recommendation is that refinement be toggleable. We adopt this directly — our hard predicate must filter the candidate set without deleting those slots from the similarity computation, or we will reproduce their regression.
  • An over-narrow predicate can empty the candidate set. For a retrieval system that is a bad day; for a cognitive system it is arguably correct behaviour (novelty = 1.0 → deliberate), but it must be a designed outcome, not an accident.
  • It says nothing about how to rank the survivors beyond cosine similarity, and nothing about affect. That is the next paper's job.
SECTION 05

KERL — subgraph-conditioned interpretation

KERL

KERL: Knowledge-Enhanced Personalized Recipe Recommendation using Large Language Models

Mohbat & Zaki · Rensselaer Polytechnic Institute · arXiv:2505.14629 · ACL 2025
Parse a constrained query into entities, pull a subgraph from a knowledge graph as context, and run three LoRA adapters over one shared base model: one selects items satisfying the constraints, one generates procedure, one generates derived quantitative attributes that were never stored explicitly.

Core mechanism

KERL is a recommendation paper, and the recipes are irrelevant to us. Three of its structural decisions are not.

Retrieval returns a subgraph, not a row. Given a query, KERL parses the tag tj and constraints, generates a SPARQL query against FoodKG, and retrieves a subgraph R(tj) — nodes plus their relations plus their attributes. That subgraph, serialised, becomes the LLM's context. The retrieved object is a piece of connected structure, and the reasoning happens over it rather than over an isolated record.

Positive/negative context construction. During training, context Cj is built from at most K/2 items from R⁺ (satisfying all constraints) and at most K/2 from R⁻ (the rest). The model learns to select from a mixed candidate set — not to rank a pre-cleaned list. Their Table 2 makes the ratio vivid: mean |R(tj)| ≈ 3167 against |R⁺| ≈ 10.67. The discrimination task is the whole point.

Multi-LoRA over one backbone. Three adapters — Recom, Recipe, Nutri — share Phi-3-mini and are swapped at inference. Each is a specialised reader of the same retrieved subgraph. The Nutri adapter is the interesting one for us: it generates micro-nutrient values from title, ingredients and steps, i.e. it produces attributes that exist nowhere in the stored record and are inferred from structure. Their Table 9 shows accuracy improves as more of the retrieved structure is supplied (calories MAE 258.28 from title alone → 221.38 with title + ingredients + instructions).

Figure 5 — KERL's shape, and the MPCS reading of it
The transferable idea is not the LLM. It is the pattern: retrieve connected structure once, then read it several ways with small specialised heads. MPCS's CurrentStatus.md lists "emotion as a first-class signal" as a top gap; KERL's Nutri adapter is a working demonstration that a derived attribute can be computed from retrieved structure rather than stored on every record.

Concretely, on our data

MPCS's _contribution_weight already computes a per-memory contribution (similarity × recency × boosts) and build_graph already emits an explanation payload naming which memories drove a decision. KERL tells us what that machinery is short of: the retrieved set is used only to produce a scalar reward estimate. Three heads over the same retrieved subgraph would produce (a) the action value we already compute, (b) a valence/arousal pair inferred from the reward distribution and the hard-predicate hits across the subgraph, and (c) the natural-language trace the dashboards want. Each is cheap; none requires a second retrieval.

Which MPCS problem this solves

Concern D, and the interpretation half of A. It converts retrieval from "return k records" into "return a reading of the situation" — action value, emotional colouring, and a defensible explanation, all conditioned on the same retrieved structure. It also supplies the discrimination framing: like KERL's R⁺/R⁻ split, our detailed ranker should be trained to select from a candidate set that deliberately contains near-misses, which is exactly what §3 and §4 hand it.

What it does not solve

  • KERL's own limitation section is blunt: if no item in the KG satisfies all constraints, the system returns nothing, and incorrect context yields incorrect output. Retrieval quality bounds everything downstream — which is why layers B and C must come first.
  • Their qualitative Table 14 shows the selector emitting false positives and dropping true positives even at F1 0.97. A head is a heuristic, not a guarantee; safety-critical routing must stay with the reflex rules, not the learned head.
  • The paper is offline, batch, GPU-bound. MPCS is an interactive per-step loop. Our heads must be small — linear or shallow MLP over the retrieved contributions — not fine-tuned language models.
SECTION 06

Why the three are complementary

They are complementary because each operates at a different point on the precision/cost curve, and each fails in a way the next one covers.

Figure 6 — Cost per candidate against selectivity: the three papers occupy different regimes
Each stage's weakness is the next stage's premise. HMGI is fast and imprecise, so it must be followed by a precision filter; HyST is precise but has no way to avoid a scan, so it must be preceded by a screen; KERL is rich but costly, so it must be given a small set.

A caution on transferring numbers

None of the reported figures — HMGI's 0.22 ms latency, HyST's 0.9211 P@1, KERL's 0.973 F1 — transfer to MPCS. They were measured on different data, at different scales, with different hardware, and HMGI's own paper flags that its results so far cover up to 50K queries with full-scale evaluation still pending. What transfers is the architecture: the layering, the separation of hard from soft, the one-retrieval-many-heads pattern. Everything quantitative must be re-measured on our workload, which is why §11 puts instrumentation before optimisation.

SECTION 07

The unified MPCS memory architecture

Five layers, L0 through L4, matching the five concerns of §2. Layers are strictly ordered on the read path and strictly ordered in reverse on the write path.

Figure 7 — The proposed five-layer perceptual memory stack
The reflex short-circuit is deliberate and is our addition, not any paper's. If a reflex rule fires or novelty exceeds θ, the system must act without paying for L3 — a cognitive architecture that cannot answer quickly under threat has the wrong shape regardless of its retrieval quality.

L0 · Multisensory representation

An episode becomes a record with four facets rather than one tuple.

# Proposed episode record Episode = { Φ: { thermal:(hot,.95), contact:(firm,.95), odor_type:(smoke,.70), ... } # structured, filterable E: { vision:ℝ⁴⁸, audio:ℝ²⁴, touch:ℝ⁴⁰, smell:ℝ³² } # dense, per modality G: { object:o₇, action:withdraw, prev:e₄₀, outcome:e₄₂ } # typed edges A: { reward:0.08, valence:−0.82, arousal:0.91, step:41, decay:0.99ᵗ } # affect + bookkeeping }
Φ is what HyST filters on and what the current engine already stores. E is what HMGI indexes; for categorical features the encoder is a learned embedding table per (feature, value) pair, mean-pooled per modality and scaled by the Z-confidence — the confidence weighting the engine already applies, moved into the vector so the ANN index respects it. G is what KERL walks. A is the gap CurrentStatus.md names; valence and arousal are derived at write time from the reward and the hard-predicate hits, in the spirit of KERL-Nutri, rather than being asked of the user.

L1 · Fast index screening

One HNSW-style index per modality partition, probed only for the modalities the percept actually contains — which is directly enabled by MPCS's existing malleability property, where any channel may be omitted. Writes go to an MVCC delta scanned brute-force alongside the index. The dlCBF stays, demoted to exact-duplicate detection at write time, where its O(1) answer is the right answer.

L2 · Similarity-sensitive novelty

Hard predicate first, graded kernel second, over the L1 candidates only. Slot classification (hard vs soft) is initialised from the existing REFLEX_RULES — every feature appearing in a reflex condition is hard by construction, which gives the split a principled starting point rather than a hand-tuned one — and thereafter adjusted by the L4 weight update.

L3 · Detailed retrieval

Two-hop subgraph expansion around the admissible set, fused ranking by HMGI's Eq. 3 modulated by the existing recency decay, then three lightweight heads. HEAD-A reproduces today's reward_from_memory; HEAD-E is new; HEAD-X formalises the explanation payload the dashboards already draw.

L4 · Update and learning

Three writes per step, none of which touch the index structure: the episode appends to the delta; the slot weights ω and the fusion weights wv, wg take a gradient step on the reward prediction error; re-partitioning and delta merging run asynchronously when the loop is idle. This closes the "triple-update loop" gap in CurrentStatus.md — memory store, salience weights, and routing threshold all moving together.

SECTION 08

Running example: the hot pan

One stimulus, traced through all five layers. Numbers are illustrative and consistent with the engine's current defaults (top_k=5, time_decay=0.99, novelty_threshold=0.5, action_threshold=0.5) against a hypothetical store of 40 000 episodes.

Figure 8 — End-to-end trace: stimulus to memory update

Stimulus

The agent's hand approaches a dark, motionless object on a stove. Vision reports a dark static unknown at full confidence; touch reports firm contact on a rough hot surface at 0.95; smell reports smoke at 0.70. Audio is absent — a channel MPCS is explicitly allowed to omit.

Percept construction (L0)

The four facets are assembled. Note that Φ and E carry the same information in two forms on purpose: Φ so it can be filtered exactly, E so it can be compared approximately.

Φ = {object_type:(unknown,1.00), motion:(static,1.00), color:(dark,1.00), contact:(firm,0.95), texture:(rough,0.95), thermal:(hot,0.95), odor_type:(smoke,0.70), odor_intensity:(moderate,0.70)} E = {vision: ℝ⁴⁸, touch: ℝ⁴⁰, smell: ℝ³²} audio: absent hard(p) = thermal ∈ {hot} AND odor_type ∈ {smoke} ← from REFLEX_RULES membership soft(p) = {object_type, motion, color, texture, odor_intensity}

Indexing / screening (L1)

Partitions P₁ (vision), P₃ (touch), P₄ (smell) are probed; P₂ (audio) is skipped entirely. Each probe is an HNSW descent, not a scan. The delta store — 37 episodes written since the last merge — is scanned brute-force and unioned in.

probe P₁ → 180 probe P₃ → 150 probe P₄ → 120 delta → 37 union, dedupe → 412 candidates dlCBF: exact key not present → this is not a literal repeat (used at write time only)

Familiarity / novelty evaluation (L2)

The hard predicate runs first and is brutal: of 412 candidates, 6 were both hot and smoky. Among those six, the graded kernel over soft slots finds the closest at 0.29 — a hot smoky episode involving a fast-moving bright object, which shares the danger but little else.

hard predicate 412 → 6 admissible best soft match sim = 0.29 (e₁₉₀₃: hot, smoke, bright, fast, smooth) novelty ν = 1 − 0.29 = 0.71 ν > novelty_threshold (0.50) ↳ compare with today's kernel: nearest overall was e₂₂₄ at 0.83 → ν = 0.17 e₂₂₄ was thermal=neutral. It is not in the admissible set at all.

This is the single most important step in the example. The old kernel called this situation familiar and safe; the new one calls it dangerous and largely unprecedented, and it is right.

Candidate retrieval (L3a)

The six admissible episodes are expanded two hops: same-object edges pull in three earlier encounters with the same stove; same-action edges pull in four prior withdraw outcomes; temporal-adjacency edges pull in what happened immediately after each. Fourteen nodes total.

hop 0 e₁₉₀₃ e₂₀₄₄ e₂₁₁₇ e₂₂₈₀ e₃₀₀₁ e₃₄₉₂ (admissible) hop 1 +o₇ stove → e₈₈₀ e₉₀₂ e₁₄₅₅ (same object) hop 2 +act:withdraw → e₉₀₃ e₁₄₅₆ e₂₀₄₅ e₃₄₉₃ (outcome of the action) → 14-node subgraph

Detailed ranking (L3b)

Fused scoring ranks the subgraph; the three heads read it. HEAD-A finds withdraw dominant with mean reward 0.86 against 0.11 for approach. HEAD-E returns strongly negative valence with high arousal — derived from the reward distribution and the hard-predicate density in the subgraph, not stored anywhere. HEAD-X names the evidence.

rank episode S = wᵥ(1−dᵥ) + wg·ḡ × recency action reward 1 e₂₁₁₇ 0.62 + 0.29 × 0.94 withdraw 0.91 2 e₃₄₉₂ 0.58 + 0.31 × 0.88 withdraw 0.88 3 e₁₉₀₃ 0.71 + 0.14 × 0.79 withdraw 0.83 4 e₂₀₄₄ 0.49 + 0.27 × 0.91 alert 0.74 5 e₉₀₂ 0.31 + 0.44 × 0.72 approach 0.11 ← same object, bad end HEAD-A withdraw 0.86 | alert 0.74 | observe 0.40 | approach 0.11 | ignore 0.22 HEAD-E valence −0.74 arousal 0.88 HEAD-X "hot + smoke, 6 matching episodes, 5 ended in withdraw or alert; the one approach on this object (e₉₀₂) scored 0.11."

Because the reflex rule thermal=hot → withdraw also fires, L3 runs in parallel with the action rather than gating it: the agent withdraws first and the ranking arrives to justify, weight and record the choice. That ordering is our design decision, and it is why the reflex lane in Figure 7 bypasses L3.

Memory update (L4)

The new episode is appended to the delta with its derived affect. Because ν was high and the outcome confirmed the retrieved recommendation, the slot weights shift toward the features that carried the prediction, and the fusion weights shift slightly toward the graph term, which contributed the decisive e₉₀₂ evidence.

append e₄₁ → delta (38 pending) index untouched reward 0.89 vs HEAD-A prediction 0.86 → error +0.03 ω[thermal] 0.94→0.95 ω[odor_type] 0.88→0.90 ω[color] 0.41→0.40 wg 0.35→0.36 action_threshold 0.500→0.507 (novelty_gain = 0.5+ν) async queue: merge delta when idle; re-fit P₃ centroids after 500 writes
What the example demonstrates

The three papers do not overlap anywhere in this trace. HMGI acts once, at step 3, and never looks at meaning. HyST acts once, at step 4, and never looks at cost. KERL acts once, at steps 5–6, and never looks at either. The layering is what turns a 10⁶-comparison scan that reached the wrong conclusion into a ~2 ms cascade that reached the right one.

SECTION 09

Cost, limits and honest failure modes

LayerMakes cheaperCost it addsLimitation / when it hurts
L1 screening
HMGI		 Novelty + retrieval drop from two O(N·d) scans to O(log N) per probed partition. Skipping absent modalities is free selectivity. Index build and periodic re-fit; embedding tables; memory for four HNSW graphs. Below roughly 5 000 episodes the constant factors likely exceed the saving — a linear scan over 2 000 records is already sub-millisecond. Partitioning also hurts genuinely cross-modal recall: HMGI itself concedes multimodal systems favour dominant modalities, and a percept whose signal lives in the combination of touch and smell may be found in neither partition alone.
L2 novelty
HyST		 Precision: the expensive L3 stage sees ~40 rather than ~400 items. Also removes an entire class of dangerous false-familiarity. One predicate evaluation per candidate; the hard/soft slot classification must be maintained. An over-narrow predicate empties the candidate set and the agent is permanently novel — hesitating forever. HyST's own ablation shows query refinement can reduce precision when the "soft" part carried real signal, so we filter without deleting. Slot classification is also a policy choice with safety consequences: mark too few features hard and the old pathology returns.
L3 retrieval
KERL		 One retrieval, three read-outs. Affect becomes derivable rather than stored, so no per-episode annotation burden. Two-hop graph walk; three small heads to train and keep calibrated. Garbage in, garbage out — KERL's stated limitation. The heads are heuristics that will emit false positives at any accuracy short of perfect (their Table 14 shows this at F1 0.97), so safety routing must remain with the deterministic reflex rules. Derived valence is also a modelling assumption, not a measurement; if reward is sparse or noisy the affect signal is decorative.
L4 update
HMGI + ours		 Removes index rebuild from the interactive path entirely; HMGI reports 50 ms vs 250 ms update latency with vs without a delta store. Delta scan cost grows until merge; two consistency regimes to reason about. If merges are deferred too long the delta becomes the dominant scan and L1's advantage erodes. Weight updates on ω risk slow drift toward whatever the agent happens to encounter, which is learning working correctly and looking like a bug.
dlCBF
demoted		 O(1) duplicate detection when loading preset memory or accepting expert teaching, where keys genuinely repeat. Negligible; it is already built. Useless on the read path, as measured. Keeping it anywhere else would be sunk-cost reasoning.
The scale question, stated plainly

MPCS today runs interactive sessions with hundreds of memories. At that scale this entire architecture is over-engineering, and a fair reading of the evidence says so. Its value is conditional on the store growing by two or three orders of magnitude — which the preset-memory and long-run experiment tracks make plausible, but not yet true. The correct response is not to build it all now; it is to build L0 and L2 now (they improve correctness at any scale, and L2 fixes a real safety pathology), instrument the loop, and gate L1, L3 and L4 on measured scan cost.

SECTION 10

Provenance: papers vs. our proposal

SECTION 11

Proposed stack and build order

L0
Four-facet episode record — Φ structured · E dense per modality · G typed edges · A affect
Replaces the flat summary tuple. Backwards-compatible: Φ is the current summary, everything else is additive. Build first — every other layer reads it.
L2
Hard-predicate filter + graded soft kernel, slots seeded from REFLEX_RULES
Build second, ahead of the index. It is a pure correctness fix, costs nothing at current scale, and closes the false-familiarity failure demonstrated in §8 step 4.
—
Instrumentation: per-step scan cost, candidate counts, novelty distribution
Build third. This is the gate. L1 and L4 are justified only once measured scan cost is actually a problem — the Bloom-filter result is the standing reminder of what happens when it is assumed instead.
L3
Two-hop subgraph expansion + HEAD-A / HEAD-E / HEAD-X over fused ranking
Build fourth. HEAD-A largely exists as reward_from_memory; HEAD-X largely exists as the explanation payload. HEAD-E is genuinely new and should ship behind a flag with its outputs logged before they influence any decision.
L1
Per-modality ANN partitions + MVCC delta; dlCBF demoted to write-time dedupe
Build fifth, when instrumentation says so. Ship with a linear-scan fallback and a correctness harness that asserts the indexed top-k matches the exhaustive top-k on a held-out set.
L4
Triple update — episode append, ω / wv / wg gradient step, async merge and re-partition
Build last. The weight-learning half closes the salience-weight gap named in CurrentStatus.md; the async half is only needed once L1 exists.
The one-paragraph answer to the driving question

Represent each experience as four facets — filterable structure, per-modality dense vectors, typed relational edges, and derived affect — so that different questions can be asked of different facets. Screen for familiarity with modality-partitioned approximate neighbour search over an append-tolerant index, not with exact membership, because perceptual experience never repeats bit-for-bit. Judge novelty only among memories that satisfy the percept's safety-critical constraints, so that four matching decorative features can never argue the system out of alarm. Retrieve in detail by expanding a small subgraph around the survivors and reading it three ways — action value, emotional colouring, and explanation — from a single retrieval pass. Update by appending to a delta and nudging the slot and fusion weights, never by rebuilding the index on the interactive path. The layering is the contribution; each layer is cheap precisely because the one before it did its job.
