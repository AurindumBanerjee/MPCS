Technical Research Report · Memory Subsystem Design

Perceptual Memory Indexing and Retrieval

Integrating HMGI, HyST and KERL into the memory layer of a malleable perceptual-cognitive system
Design study Memory · Indexing · Retrieval 2026 HMGI · HyST · KERL
Abstract

Our perceptual-cognitive system stores every experience as a multimodal percept with per-channel confidence, and decides what to do next by comparing an incoming percept against those stored experiences. That comparison is currently exhaustive: every stored record is scored for every candidate action, and novelty is defined as one minus the best score found anywhere in memory. It is correct, fully explainable, and linear in the size of memory. Hash-based membership screening was evaluated as a way out of that scan and did not deliver a useful speedup, because a bare membership test only recognises verbatim repeats — and a perceptual system almost never sees the same twelve-feature configuration twice.

This report examines three retrieval papers — HMGI (hybrid multimodal graph indexing), HyST (hybrid retrieval over semi-structured data), and KERL (knowledge-graph-augmented recommendation) — and shows what each contributes to the specific problem we have. HMGI supplies similarity-sensitive indexing partitioned by modality, a fusion score that combines vector proximity with relational structure, and a delta-store update discipline for write-heavy workloads. HyST supplies the separation of hard structured constraints from soft semantic preference, so that filtering happens in metadata rather than inside the similarity function. KERL supplies constrained selection over a retrieved subgraph, and a training regime that teaches a selector to reject plausible near-misses. We then synthesise them into a five-layer memory stack — representation, screening, novelty, ranked retrieval, and update — and trace one stimulus end to end through it.

§ 01

The retrieval problem we actually have

Every cognitive step in our system asks memory three questions in quick succession, and the quality of the whole step depends on all three being answered well.

Question 1
Is this new?
Novelty drives exploration pressure and the size of the threshold update. It must be graded, not binary: "somewhat familiar" is the common case.
Question 2
What does it resemble?
Which past experiences are close enough in meaning, feeling and context that their outcomes should be borrowed for this one?
Question 3
What did those cost?
Each retrieved memory carries an action and a reward. Their weighted verdict becomes the score for each candidate action, and the basis of the penalty rule.

Today all three are answered by the same operation: a full pass over stored experience, computing a confidence-weighted, key-aligned match between the incoming percept and every record. This is honest and interpretable — every number in the explanation payload traces back to a specific stored memory — but it has three structural weaknesses.

Diagram 1 — Where a step's memory cost goes today

The three weaknesses, stated precisely

  • Linear novelty. Novelty is the complement of the best similarity found across all of memory, which means the answer to a cheap question costs a full traversal. As sessions lengthen, the cheapest question becomes the most expensive one.
  • Filtering by scanning. Retrieval-for-scoring restricts candidates to those sharing a given action, but it discovers that restriction by walking the whole store and discarding non-matches. A structural property known before the scan is being paid for during it.
  • One similarity for everything. Semantic overlap ("both involve smoke"), emotional alignment ("both were high-arousal and negative"), contextual match ("both in the kitchen, both at night") and relational proximity ("this followed the same event that preceded that one") all collapse into a single confidence-weighted feature count. Nothing lets the system weight them differently for different situations.

The three papers address these three weaknesses almost one to one, and they do it at different layers of the stack, which is why they compose instead of competing.

§ 02

Why a membership filter was the wrong tool

Before the papers, it is worth being precise about what the earlier hash-based screening attempt could and could not do, because the shape of that failure determines what a replacement has to provide. Current system

A counting membership filter answers exactly one question — has this exact key been inserted before? — in constant time and tiny space. For a perceptual percept, the key is the full feature configuration. With four modalities and twelve categorical features, the space of distinct configurations is combinatorially large, so two experiences that a human would call "the same kind of moment" almost never produce the same key. The filter therefore reports "unseen" for nearly every percept, and the answer, while correct, carries no usable information. The screen never screens anything out, so no downstream work is avoided, and the measured speedup is roughly zero. Its remaining honest use is as an exact-repeat hint: a signal that this precise configuration has recurred verbatim.

Diagram 2 — Binary membership versus graded similarity on the same percept stream
The requirement this leaves behind

A screening layer for a perceptual system must be either similarity-sensitive (near-misses count as hits, with a graded score) or attribute-sensitive (it prunes on declared structural properties, not on a hash of the whole configuration). HMGI supplies the first; HyST supplies the second. Neither is a replacement for a membership filter — both are replacements for the linear scan the membership filter failed to avoid.

§ 03

HMGI — similarity-sensitive multimodal indexing

The Hybrid Multimodal Graph Index
Chandra, Navneet & Zhang · a framework unifying relational traversal and vector similarity search
The paper's premise is that vector databases and graph databases each solve half of a single problem: one finds semantically close items but cannot reason over the relationships between them, the other traverses relationships but has no native notion of semantic proximity. HMGI proposes holding both in one index — embeddings stored as node properties, relationships as edges — so a query can move between them without leaving the system.

Core mechanism

Four ideas do the work. From the paper

  • Modality-aware partitioning. Rather than pooling all embeddings into one monolithic index, embeddings are separated by their source modality and clustered within each partition. A query touching one modality only searches that partition, which shrinks the region scanned and lets each partition be tuned independently. The paper attributes a large reduction in searched space to this, and its ablation reports that removing partitioning both slows queries and degrades cross-modal recall as clusters dilute.
  • Graph-based approximate nearest neighbour search. A hierarchical proximity graph is traversed greedily from sparse upper layers into dense lower ones, giving query cost that grows logarithmically rather than linearly with the number of stored vectors.
  • Fusion scoring. A candidate's final score blends its vector proximity with the scores accumulated along a short graph traversal, under weights that can be set at query time — so the balance between "semantically close" and "structurally connected" is a runtime decision, not a build-time one.
  • Adaptive updates. New and changed items land in a delta store under multi-version concurrency control; queries hit the stable index plus a brute-force pass over the small delta, and the delta is merged into the main index asynchronously. The paper's ablation reports that removing this forces full rebuilds, inflating update latency several-fold and causing query downtime.
Fusion score (paper form) S = w_v · (1 − d_v) + w_g · (1/h) · Σᵢ₌₁..h s_gᵢ d_v normalised vector distance to the query embedding s_gᵢ score contributed by the i-th hop of the graph traversal h number of hops; w_v, w_g set per query, not fixed at build time
Diagram 3 — HMGI: partitioned similarity search, then relational expansion

A concrete example, in the paper's own domain

Suppose the query is a photograph of an apple and the intent is "find the product, not the fruit". A pure vector search returns whatever is visually nearest, which may be either. In HMGI, the image embedding is searched inside the image partition, the returned nodes become entry points, and a short traversal over their relationships — manufacturer, product line, category — supplies the evidence that separates the two senses. The fusion weights decide how much of the verdict comes from "looks like" and how much from "is connected to". The paper reports that partitioned strategies are notably better at exactly this kind of disambiguation than unified embeddings, at the cost of extra storage for the separate indexes.

The problem it solves in our system

This is the answer to weakness one and weakness three. Our integration

  • Novelty becomes a top-1 lookup. Instead of scoring all of memory to find the maximum similarity, we ask the index for the nearest stored percept and take one minus its similarity. Traversal replaces enumeration.
  • Modality partitions match the malleability property directly. Our percepts already omit modalities freely; a partitioned index turns that absence into a search-space reduction rather than an awkward gap in a fixed-length key. A percept with only audio and smell active searches two partitions and pays nothing for vision or touch.
  • The graph half gives us relational memory we do not currently have. Successive percepts within a session, percepts that share a reflex rule, and a corrected step and its expert teaching record are all naturally edges. A one-hop expansion lets a memory be retrieved because of what it was next to, not only because of what it looked like.
  • Fusion weights give the balance a dial. Under high novelty we can raise the relational weight, since vector proximity is by definition weak; under high familiarity we can lean on proximity and skip the traversal.
Makes cheaper
  • Nearest-neighbour lookup: sub-linear traversal instead of a full pass
  • Per-modality search space, so absent channels cost nothing
  • Insertion: appended to a delta, merged in the background
  • Storage: quantised embeddings shrink the resident footprint
Costs added
  • An embedding function per modality that we do not have today
  • Index structure to build and maintain alongside the record list
  • Approximate results: the true nearest neighbour can be missed
  • Two extra weights and a hop budget to tune
Limitations to respect
  • The paper's own limitations section flags fusion latency overhead and update-time recomputation
  • Its benchmarks are billion-scale; our store is thousands, where a graph index can lose to a scan
  • Approximation weakens the guarantee that every contributing memory is found
  • Embedding quality for weak channels (smell, proprioception) is acknowledged as underdeveloped
Scale caveat, stated plainly

HMGI's reported gains come from datasets many orders of magnitude larger than an interactive session's memory. Below roughly a few thousand records a linear scan over compact tuples is likely to beat a graph traversal on wall-clock time. We therefore propose the index as a structure that activates above a configured record count, with the existing exhaustive path retained as the exact reference and as the fallback below that threshold.

§ 04

HyST — hard constraints before soft similarity

HyST: hybrid retrieval over semi-structured tabular data
Myung, Park & Han · structured filtering and semantic search in one retrieval pass
HyST starts from a failure mode rather than an architecture. Real queries mix requirements that must hold — a brand, a category, a price ceiling — with preferences that are matters of degree, like a cosy atmosphere. Flatten both into one string and embed it, and the retriever will happily return a French restaurant for an Italian query, because "French" is semantically near "Italian" and nothing in the pipeline treats the category as binding.

Core mechanism

The pipeline has three stages. From the paper

  1. Filter generation. A language model reads the query and emits attribute-level conditions in the operator vocabulary the vector store already understands — equality, list membership, less-than, ranges. These become metadata filters, not text.
  2. Query refinement. The parts already captured by the filter are removed, leaving a concise semantic query describing only the subjective remainder.
  3. Filtered hybrid retrieval. The store applies the metadata conditions first to narrow the candidate set, then ranks the survivors by embedding similarity to the refined query.

Two results from the paper matter for us more than the headline numbers. The first is the case analysis: where semantic-only retrieval returned an item of the wrong brand because it was textually similar, the filtered pipeline could not, because the wrong brand was excluded before ranking began. The second is the ablation on stage two — removing query refinement slightly improved precision at deeper ranks, because the unstructured text already carried structured cues, and stripping them discarded useful signal. The authors' own conclusion is that refinement should be treated as optional and dataset-dependent.

Diagram 4 — HyST applied to a percept query in our system

The problem it solves in our system

This is the answer to weakness two, and it is the honest replacement for the membership screen. Our integration

Our per-action retrieval is already, conceptually, a metadata filter: it wants records whose action equals the candidate action. It just implements that want as a scan. Promoting it to a declared filter over stored attributes turns it into a cheap pre-selection. And once the mechanism exists, more of our structure fits into it than just the action:

What HyST costs us — almost nothing

Unlike HMGI, this layer needs no new mathematics and no embedding model. It needs the record store to keep an attribute index over fields it already writes, and the retrieval calls to declare which of their conditions are binding. It is the cheapest of the three integrations and, at our current store size, likely the largest immediate saving: it removes candidates before any similarity arithmetic occurs.

Limitation carried over

HyST's filters are only as good as the extraction that produces them, and the paper reports a hallucinated attribute name in its own evaluation. Our advantage is that our schema is fixed and small — modalities, actions, modes, flags are enumerated in code — so filter construction is deterministic rather than generated. Where it is not (a free-text context descriptor), the paper's warning applies directly: over-strict filtering on a fine-grained vocabulary silently empties the candidate set. Any binding filter we add needs a defined behaviour for "zero survivors", which should be relaxation to the soft path, not a cold-start fallback.

§ 05

KERL — constrained selection over a retrieved subgraph

KERL: knowledge-enhanced personalised recommendation
Mohbat & Zaki · knowledge-graph retrieval feeding a constrained generative selector
KERL handles requests carrying many simultaneous conditions — include these ingredients, exclude those, keep a nutrient inside a range — over a knowledge graph of a million recipes. Its structure is retrieval followed by judgement: parse the query into entities, pull a relevant subgraph, serialise it as context, and let a fine-tuned model select from that context the items that actually satisfy every condition. Separate lightweight adapters over one shared base then produce the downstream outputs.

Core mechanism

  • Entity parsing to structured query. Tags and entities are extracted from the natural-language question and used to build a query over the knowledge graph from templates, returning a subgraph rather than a single answer. From the paper
  • Subgraph as context. The retrieved subgraph — names, ingredients, nutrition — is serialised and handed to the model as the ground it must reason over. The model selects; it does not invent. The paper is explicit that nothing outside the retrieved set can be recommended.
  • Positive and negative sampling. During training each context deliberately mixes items that satisfy the constraints with items that do not, in balanced proportion, even though satisfying items are rare in the underlying data. The selector is trained on the discrimination, not on the prior.
  • Multiple adapters, one base. Selection, step generation, and nutrient estimation each get their own small adapter over a shared backbone, so the specialised behaviours are separable and cheap while inference remains single-model.

The paper's qualitative table is the instructive part: it shows the selector returning a false positive in one case, and in another returning an item that was not in the provided context at all. Retrieval bounds what can be selected, but does not by itself guarantee that the selection is correct — a distinction that matters for us, because our equivalent of "selection" directly becomes an action.

Diagram 5 — KERL's retrieve-then-select shape, mapped onto our decision step

The problem it solves in our system

HMGI and HyST both make retrieval cheaper. KERL is the only one of the three that speaks to what happens after retrieval — and it maps onto the part of our system that turns retrieved memories into a decision. Our integration

  • Grounded scoring as a contract. KERL's insistence that recommendations come only from the retrieved subgraph is already our practice: an action's score comes from memories that were recalled for it, and a score with no support is reported as unsupported rather than dressed up as a recommendation. Adopting it explicitly means the retrieval set becomes the sole admissible evidence for the step, and the candidate-set boundary becomes a checkable property rather than an implicit one.
  • Negative sampling for the near-miss problem. This is the genuinely new idea for us. Our scoring is a weighted average of rewards over the top-K by similarity, which cannot distinguish "similar and it went well" from "similar but the one differing feature is precisely the one that mattered". Under HMGI's approximate retrieval that risk increases. Constructing training or calibration batches that deliberately pair a satisfying memory with a near-miss that violates one binding condition is the paper's answer, and it transfers directly: we can calibrate the contribution weighting on those pairs rather than assuming similarity is monotone in relevance.
  • Separable heads over shared retrieval. KERL's multi-adapter arrangement suggests factoring our post-retrieval stage into three small consumers of one candidate set — an action scorer, a reward estimator, and an explanation builder — rather than one function computing all three inline. Retrieval is paid once; the specialised readers are cheap.
  • Constraint satisfaction, made explicit. KERL checks retrieved items against numeric and set conditions. Our analogue is checking that a retrieved memory's active modalities cover the features the current decision depends on. A memory recorded without touch should not carry weight in a thermal-driven withdrawal.
Makes cheaper
  • Reasoning is confined to a bounded candidate set instead of the whole store
  • Small task-specific heads over shared retrieval, rather than duplicated passes
  • Discrimination is learned from balanced pairs, not from the raw skew of the data
Costs added
  • A calibration set of near-miss pairs must be constructed and maintained
  • A learned scorer is less transparent than a weighted average
  • Adds a training loop to a system that currently only updates online
Limitations to respect
  • The paper reports both false positives and selections outside the provided context
  • Nothing can be recommended if retrieval returns nothing relevant — the empty-candidate path must be designed, not defaulted
  • Retrieval quality caps everything downstream; a good selector cannot repair a bad candidate set
§ 06

Synthesis: the five-layer memory stack

The three papers sit at three different depths, which is what makes the combination coherent rather than redundant. HyST decides which records are even eligible. HMGI decides which eligible records are close, and how cheaply that can be discovered. KERL decides what a close record is allowed to justify. Around those, our existing representation and update machinery form the first and last layers.

Prune on what is binding, index on what is graded, and let only what was retrieved speak.

§ 07

Layer A — Multisensory memory representation

The representation layer must hold three things that are frequently conflated: what was sensed, how reliable each channel was, and the structural facts about the episode. The current design already separates the first two — each feature is a value with a confidence, and confidence is a property of the channel, so a low-reliability channel contributes proportionally less to any match. The proposal keeps this and adds two things.

Kept
Slot-stable summary
One slot per modality in fixed order; an absent modality yields an empty slot rather than shifting the others. Slot position always identifies the channel.
Added
Per-modality embedding
Each non-empty slot also produces a vector, so similarity can be approximate and indexable rather than exact and enumerated.
Added
Metadata envelope
The structural facts — active modalities, action, mode, reflex rule, expert flag, step — declared as filterable attributes rather than discovered by scanning.
Added
Episode edges
Links to the preceding step, to records sharing a reflex rule, and from a corrected step to its expert record. The relational half of HMGI's index.
Diagram 7 — The extended memory record
Design decision: embed per modality, not per percept

A single joint embedding of the whole percept would be simpler, but it destroys the malleability property. Two percepts that agree completely on audio and differ only in whether vision was available would sit far apart in a joint space, because the absent channel has to be encoded as something. Per-modality vectors let absence be expressed as absence: the audio partition compares audio to audio, and nothing invents a vision reading that was never taken. This mirrors HMGI's own argument that unified embeddings suffer a bias toward dominant modalities.

§ 08

Layer B — Fast membership and index screening

This layer answers "which records could possibly be relevant?" and it answers it without arithmetic. Its inputs are the metadata envelope of the query and the attribute indexes over the store; its output is an eligible subset. The critical property is that it is lossless with respect to the binding conditions: nothing it discards could have been a valid contributor.

Why this specifically replaces the failed screen

The membership filter failed because its key was the whole configuration, which is almost never repeated. The attribute filter succeeds because its keys are the few coarse properties that genuinely partition memory — five actions, sixteen modality subsets, a handful of modes. Those are repeated, constantly, and each one cuts the candidate pool by a large fraction. The lesson is that the screen must be built on the low-cardinality structure of memory, not on its high-cardinality content.

§ 09

Layer C — Similarity-sensitive novelty detection

Novelty in our system is not a diagnostic readout: it sets exploration pressure and scales the size of every threshold update, so it is consumed on every step and must be both cheap and well-behaved. The proposal keeps the definition and changes only how the maximum is found.

Novelty, before and after now novelty = 1 − maxm ∈ Memory sim(Q, m) O(N) — every record scored proposed novelty = 1 − Σk αk · simk( Qk , nearestk(Qk) ) O(log N) per active partition k ranges over active modalities only; αk is the channel confidence, renormalised over the active set, so an unreliable channel cannot by itself declare a percept familiar.

Two properties are worth stating because they change behaviour, not just cost. Our integration

  • Novelty becomes per-channel. A percept can now be familiar in audio and novel in smell, and the aggregate reflects both weighted by reliability. A single scalar over a flat feature match cannot express that, and it is precisely the situation a partially-observed environment produces most often.
  • Approximation biases toward higher novelty. Missing the true nearest neighbour means the best similarity found is too low, so novelty is over-reported. This is the safe direction: over-reported novelty raises exploration and enlarges the threshold update, which is a mild inefficiency. Under-reported novelty would suppress exploration on a genuinely unfamiliar percept, which is a failure. The error mode should nonetheless be bounded by periodically checking the index answer against an exact scan and tracking the gap.

§ 10

Layer D — Semantic, emotional and contextual retrieval

This is where the third weakness — one flat score for four different kinds of match — is finally addressed. The candidate set arriving from Layers B and C is small and already eligible. What remains is to score each candidate along separable axes and combine them under weights that the system can adjust.

Fused relevance, per candidate memory m R(m) = w_s·sim_semantic(Q, m) confidence-weighted feature/embedding proximity + w_e·sim_emotional(Q, m) closeness in valence–arousal space + w_c·sim_context(Q, m) situational descriptor overlap + w_g·(1/h)·Σᵢ s_gᵢ(m) HMGI graph term over h hops of episode edges Contribution weight (feeds scoring, reward and explanation) ω(m) = R(m) · decay^age(m) · boost(m) boost still lifts expert records and, on a reflex valuation, reflex-mode records; Σω over the retrieved set remains the support measure — a high score with low support is reported as a guess, not a recommendation.

The four terms are separable for a reason: they should not carry equal weight in every situation. Our integration

The near-miss guard, from KERL

Fusion and approximation both make it easier for a memory to score highly while differing on the one feature that determined the outcome. The guard is a check, not a weight: before a candidate contributes, verify that its active modalities cover the features the current decision actually depends on. A thermal withdrawal cannot be justified by a memory recorded with no touch channel, however similar it looks in audio. Candidates failing the check are excluded and, following KERL's negative-sampling idea, retained as calibration pairs — a satisfying memory beside a near-miss — for periodically re-tuning the fusion weights.

§ 11

Layer E — Memory updating and learning

Our workload is unusual for a retrieval system: every single step writes exactly one new record, and that record must be visible to the very next step. A conventional index rebuild cadence is unusable here, which is exactly the situation HMGI's update mechanism was designed for.

Diagram 9 — Delta store: writes never block reads

This division has a pleasant consequence for correctness. The delta is scanned exhaustively, so the most recent experiences — the ones time decay weights most heavily — are always found exactly. Approximation only ever applies to older records, whose influence is already discounted. Approximation error and temporal discounting act in the same direction rather than compounding.

What learning updates, extended

  • The store. Unchanged: a record per step, with reward, mode, action and penalty; rewards editable after the fact by manual labelling or expert teaching.
  • The action threshold. Unchanged: moved by learning rate times novelty gain times reward error, so novel situations move it further.
  • The fusion weights. New. Adjusted on the same signal that already drives the off-recommendation penalty: when a well-supported recommendation was overridden and the outcome vindicated the override, the term that most strongly supported the wrong recommendation loses weight.
  • The retrieval budget. New. Top-K and hop count adapt to observed support. When the retrieved set consistently yields near-zero total weight, K is too small or the filters too strict; when extra candidates change nothing, K is too large.
§ 12

Running example: one stimulus, end to end

The stimulus

Step 412. The agent is in a kitchen in the evening. A smoke alarm sounds while its hand rests lightly on a surface that has become warm; something is moving slowly at the edge of vision. Memory holds 4,000 records from earlier steps, of which 96 are in the unmerged delta.

Diagram 10 — The full flow, with the numbers at each stage

Reading the numbers

Stage 2 — why 610

The percept requires audio and smell, which excludes every record captured in the dark or with the olfactory channel offline. Combined with the mode condition, this removes roughly six records in seven. Nothing here required a similarity computation: the filter is answered by attribute indexes over fields the record already carries. This is the stage the hash membership screen was supposed to occupy and could not.

Stage 3 — why 0.198

The four channel similarities are 0.74 / 0.91 / 0.66 / 0.88 with confidences 1.00 / 0.90 / 0.95 / 0.70. The confidence-weighted mean is 0.802, so novelty is 0.198. The percept is largely familiar in audio and smell — the agent has heard this alarm before, near this smell — and less so in touch, which is the channel that actually differs. A flat maximum over the whole feature tuple would have reported one number and lost that structure entirely.

Stage 5 — one candidate, fully decomposed

Memory m-338, recorded 74 steps ago, was an alarm-and-smoke episode that ended in alert with reward 0.88.

Semantic proximity 0.81, emotional alignment 0.77, context match 0.90 (both kitchen, both evening), graph term 0.62 (it is two edges from the current episode via a shared reflex rule). Under weights 0.40 / 0.20 / 0.15 / 0.25 the fused relevance is 0.7705. Time decay at 0.99⁷⁴ gives 0.475; no boost applies, so its contribution weight is 0.366 — the largest in the set, and the first line of the explanation the dashboard will draw.

Stage 5 — a candidate the guard removed

Memory m-207 scored 0.79 on semantic proximity: alarm present, smoke present, similar arousal. But it was recorded with no touch channel, and the current decision's distinguishing feature is thermal. Under a flat similarity it would have been the second-strongest voice in the room. The guard excludes it, and it is filed as a near-miss pair alongside m-338 for the next weight calibration.

Stage 6 — retrieval still runs on the reflex path

The smoke rule fires and the action is decided without deliberation, exactly as before. Retrieval is not wasted: the deliberative scores become the recorded alternative, the reflex-mode boost values this outcome against comparable reflex episodes, and the comparison feeds the penalty rule and the threshold update. Speed on the reflex path comes from not waiting on deliberation, not from refusing to learn from it.

The dependency runs one way and cleanly. HyST without HMGI leaves a linear scan over a smaller pool — better, but still linear. HMGI without HyST indexes records that a declared constraint would have excluded for free, spending approximate search on candidates that were never eligible. KERL without either has nothing sound to select from, since it explicitly cannot recommend outside what retrieval returned. Applied in order — prune, index, ground — each stage makes the next one's job smaller.

What we are not adopting, and why

Declined
Distributed sharding and GPU offload
HMGI's scaling apparatus targets billion-vector deployments. Our store is interactive and small; this is complexity without a matching problem.
Declined
Aggressive embedding quantisation
Memory footprint is not our constraint, and quantisation trades a small recall loss for savings we do not need. Revisit only if percept vectors grow large.
Declined
LLM-generated filter extraction
HyST needs a model because its queries are natural language. Our schema is enumerated in code, so filters are constructed deterministically — and the paper's hallucinated-attribute failure never arises.
Declined
A generative selector for actions
KERL's selection is a language-model output. Ours must be auditable and fast, and the explanation payload must stay decomposable. We take the grounding discipline and the negative-sampling idea, not the generation.
Deferred
Query refinement
HyST's own ablation found removing it sometimes helped. We would be stripping structured cues out of a percept that has few to spare, so it stays off until measurement says otherwise.
Deferred
Learned index parameter tuning
Predicting index parameters from workload features is worthwhile at scale. Below a few thousand records the parameters barely matter; adopt after the index earns its place.

Open risks

  • The crossover point is unmeasured. Every claim about the index being cheaper depends on a record count we have not established. The rollout must measure exact-scan latency against index latency on real session traces and set the activation threshold from data, not from the papers' scale.
  • Approximation weakens explainability. Today the explanation is provably complete: nothing that could have contributed was missed. Under approximate search it becomes "these are the contributors the index found". The mitigation is a periodic exact audit that reports how often the index and the scan disagree on the top contributor.
  • Embeddings for weak channels. Smell is our least reliable modality and, per HMGI's own limitations, among the least well served by standard embedding methods. Confidence weighting already discounts it; if its embedding proves uninformative, that partition can fall back to exact feature matching without disturbing the others.
  • Over-strict filters can empty the pool. A binding filter that returns nothing is worse than a slow scan, because it silently pushes the step onto the cold-start path. The relaxation order must be fixed, recorded in the explanation, and monitored.
§ 15

The proposed retrieval stack

Read top to bottom, each layer consumes the previous layer's output and hands on a strictly smaller, strictly better-qualified set.

Diagram 12 — Perceptual memory indexing and retrieval stack
  • Represent richly, index separably. Percepts keep their per-channel confidence and their tolerance for missing modalities; each active channel contributes its own vector to its own partition, so absence costs nothing and no channel is invented to fill a slot.
  • Screen on structure, not on content hashes. The properties that genuinely partition memory are few and low-cardinality. Filtering on those, before any similarity is computed, is what the earlier membership experiment was reaching for and could not deliver.
  • Make novelty graded and sub-linear. Novelty stops being the complement of an exhaustive maximum and becomes a confidence-weighted blend of per-channel nearest neighbours, with approximation error biased toward the safe direction.
  • Separate the four kinds of relevance. Semantic, emotional, contextual and relational similarity get their own terms and their own weights, so the balance between resemblance and adjacency can shift with novelty rather than being fixed at build time.
  • Let only retrieved evidence speak, and guard against near-misses. A memory contributes only if it was retrieved and only if it actually covers the features the decision turns on. Rejected near-misses become the calibration set for the weights.
  • Absorb writes without blocking reads. Every step writes; the delta keeps recent memory exact and immediately visible while merging happens off the critical path, so approximation only ever touches records that time decay has already discounted.
The memory layer's job is not to remember everything equally well. It is to make the right handful of experiences cheap to find, and to be honest about which ones it found.
