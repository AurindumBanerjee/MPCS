MPCS · Background Report · Data Structures

How Memory Is Organised

From arrays and hash tables to knowledge graphs, spatial and temporal indexes — and where the MPCS episodic memory fits among them.
Requested 08 Sep 2026 · written 28 Sep 2026 Companion: MPCS Progress Report
Summary

A memory system is only as good as its ability to find the right record quickly. This report starts from the basic structures every index is built from, then covers how three families of systems organise data: LLM knowledge graphs (facts and relations), spatial structures (where things are), and temporal and spatio-temporal structures (when things happened, and where they were then).

MPCS memory is an episodic store: percepts, actions and rewards ordered in time and linked into a graph. Today it is temporal with sensory content; it has no notion of place. The last sections map our structures onto the public ones and propose how to make MPCS truly spatio-temporal.

01

Why structure matters

Suppose memory is a list of n records and a query asks for "the records most like this one". Without structure, the only method is to look at every record: the work grows in proportion to n, written O(n). At 700 MPCS memories this takes about 5 ms. At a million it would take seconds — too slow for an agent that must react.

A data structure arranges records so a query can skip most of them. The trick is always the same: precompute something at insert time (a sort order, a hash, a tree, a set of links) that lets the query rule out large groups at once.

Cost 1
Query time
How many records a lookup touches.
Cost 2
Update time
How expensive it is to insert, change or delete. Memory changes every step, so this matters.
Cost 3
Space
Extra memory the index uses beyond the records themselves.
Cost 4
Exactness
Some structures trade a small chance of a wrong answer for large speed-ups.

Every structure below is a different trade-off between these four, tuned to a different kind of question.

02

The basic building blocks

Arrays and lists

Records stored one after another. Reading record number i is instant; finding a record by content means scanning O(n). If the array is sorted, binary search halves the range each step: O(log n). A sorted array of timestamps is already a simple temporal index.

Hash tables

A hash function turns a key into a bucket number, so looking up an exact key takes O(1) on average. Hashing destroys order and closeness: hot and warm land in unrelated buckets. Hash tables answer "is this exact thing here?", never "what is near this?".

Bloom filters — the hash table that forgets

A Bloom filter (Bloom, 1970) keeps only a bit array and several hash functions. It answers "definitely not seen" or "probably seen", using a fraction of the space. Counting and d-left variants (Fan et al. 2000; Bonomi et al. 2006) support deletion. MPCS generations G2 and G3 used these as a gate before memory — and our benchmark showed why that fails: similarity search needs near matches, and a membership filter only knows exact ones.

Trees

A binary search tree keeps smaller keys to the left and larger to the right, so a lookup walks one path from root to leaf: O(log n). Databases use the B+-tree (Bayer & McCreight 1972; Comer 1979), which gives each node hundreds of children so the tree stays only 3–4 levels deep even for billions of keys. Leaves are chained, so range queries ("all keys between 10 and 20") are a single walk along the leaves.

Trees are the key idea behind spatial and temporal indexes: nest regions (of space, or of time) inside larger regions, and skip every region that cannot contain an answer.

Inverted indexes

Instead of record → features, store feature → list of records that have it. A query intersects the lists for its features. Search engines work this way, and it is what MPCS's HMGI partitions and HyST hard-slot filter amount to: "only look at records whose thermal = hot".

03

Graphs

A graph is a set of nodes (things) joined by edges (relationships). Edges may be directed (A causes B), labelled (A is_part_of B) and weighted (how strong the link is).

RepresentationHowGood for
Adjacency matrixn × n grid; cell (i, j) holds the edge weightDense graphs, matrix maths (PageRank, GNNs). Space O(n²).
Adjacency listEach node keeps a list of its neighboursSparse graphs — nearly all real ones. Space O(n + edges). MPCS's episode graph uses this.
Edge list / triple tableOne row per edge: (from, label, to)Storage and bulk loading; the basis of RDF stores.

Moving through a graph

  • Breadth-first search explores all neighbours at distance 1, then 2, … — "everything within k hops". KERL's two-hop graph term is a bounded BFS.
  • Random walks and PageRank (Page et al. 1999) — importance is the chance a random walker ends up at a node. Personalized PageRank restarts the walk from chosen seed nodes, so it measures importance relative to a query.
  • Spreading activation (Collins & Loftus 1975) — a model of human semantic memory. Activating one concept passes a decaying share of activation to its neighbours; weakly activated nodes drop out. It is essentially Personalized PageRank with a threshold, and it is the planned "activation and pruning" step for MPCS.
04

Finding similar things

Most AI memory questions are similarity questions, not exact lookups. Two families of methods exist.

Symbolic features

Records are sets of discrete features (MPCS: thermal=hot, sound_type=alarm). Similarity counts or weights matching features. Indexes are inverted lists per feature; the hard part is deciding which features must match and which may differ — the problem HyST addresses.

Vectors (embeddings)

A neural encoder turns text, an image or a percept into a list of a few hundred numbers such that similar things end up close together. Similarity is cosine or Euclidean distance. Exact nearest-neighbour search in high dimensions degrades to a full scan (the "curse of dimensionality"), so systems use approximate nearest-neighbour (ANN) indexes:

Graph-based
HNSW
Malkov & Yashunin (2018). A layered "small-world" graph; search greedily hops toward the query from coarse to fine layers. The default in most vector databases.
Clustering
IVF
Cluster vectors with k-means; search only the few clusters nearest the query (FAISS, Johnson et al. 2019).
Compression
Product quantisation
Jégou et al. (2011). Store short codes instead of full vectors, trading accuracy for memory.
Hashing
LSH
Indyk & Motwani (1998). Hash functions that keep near points in the same bucket — the "similarity-preserving" cousin of a Bloom filter.

MPCS deliberately stayed symbolic (HMGI was built "structural only", without an ANN index): features are few and interpretable, and at 700 records a scan is fast enough. An ANN layer becomes relevant beyond ~10⁵ memories.

05

Knowledge graphs for LLMs

A knowledge graph (KG) is a graph whose nodes are entities (people, objects, concepts) and whose labelled edges are facts about them. LLMs are fluent but forget, hallucinate and cannot cite; KGs are precise and inspectable but rigid. Pairing them is one of the main routes to grounded AI (Pan et al. 2024).

5.1 Storage models

RDF triplesProperty graph
Unit(subject, predicate, object) e.g. (pan, has_temperature, hot)Nodes and edges, each with key–value properties

Adding context (time, source, confidence)Awkward: needs reification or named graphsNatural: put it on the edge

5.2 How an LLM builds a KG

Chunk

Split source documents into passages.

Extract

An LLM (or a trained model like REBEL, Huguet Cabot & Navigli 2021) lists entities and the relations between them in each chunk.

"The pan on the stove is hot" → (pan, located_on, stove), (pan, has_state, hot)

Resolve

Merge duplicates ("the pan", "it", "frying pan") into one node, usually by embedding similarity plus LLM confirmation.

Ground

Every node and edge keeps a pointer back to the chunk it came from, so answers can cite evidence.

Summarise (optional)

GraphRAG (Edge et al. 2024) clusters the graph into communities (Leiden algorithm) and has the LLM write a summary per community, for "global" questions about the whole corpus.

5.3 How an LLM queries a KG

  • Seed then expand — embed the question, find the closest nodes in a vector index, then gather their neighbourhood. Used by most GraphRAG-style systems; LightRAG (Guo et al. 2024) does this at two levels (specific entities and broad themes).
  • Activation — HippoRAG (Gutiérrez et al. 2024) runs Personalized PageRank from the seed nodes, modelled on the hippocampal indexing theory of memory. Relevance is whatever activation reaches, which handles multi-hop questions in one step.
  • Reasoning walks — Think-on-Graph (Sun et al. 2024) lets the LLM pick which edges to follow, beam-search style, pruning weak paths as it goes.
  • Structured queries — the LLM writes SPARQL or Cypher directly (text-to-query).

5.4 Learning on the graph

KG embeddings give each node and relation a vector so missing facts can be predicted. TransE (Bordes et al. 2013) asks that head + relation ≈ tail; RotatE (Sun et al. 2019) uses rotations to model symmetry and inversion. Graph neural networks (e.g. GCN, Kipf & Welling 2017) pass messages along edges so each node's vector reflects its neighbourhood.

What carries over to MPCS

MPCS nodes are episodes, not entities, but the retrieval pattern is the same: seed by similarity (SHMF), expand through edges (KERL's episode graph), rank by propagated relevance (planned activation step), and cite the evidence (HEAD-X). HippoRAG is the closest precedent.

06

Spatial data structures

Spatial data answers where: points (a sensor), lines (a road), regions (a room). Typical queries are range ("everything in this box"), nearest neighbour ("closest exit") and spatial join ("which objects are on which tables"). A sorted list fails here because space has two or three dimensions — sorting by x scatters things that are close in y.

Four ways to divide space
Grids cut space into equal cells; quadtrees split a cell only where points crowd; k-d trees alternate x and y splits at data points; R-trees group nearby objects into (possibly overlapping) bounding boxes.
StructureIdeaStrength / weakness
Uniform grid, geohash, S2, H3Fixed cells, each with an ID; geohash / S2 / H3 give hierarchical cell IDs usable as hash or B+-tree keysSimple and fast to update; wastes cells where data is sparse
Quadtree / octree (Finkel & Bentley 1974)Recursively split a square into 4 (a cube into 8) where it holds too many pointsAdapts to density; the standard for 3D robot maps (OctoMap)
k-d tree (Bentley 1975)Binary tree splitting on one coordinate per levelExcellent nearest-neighbour search in low dimensions; costly to rebalance
R-tree (Guttman 1984), R*-treeB-tree of bounding rectanglesHandles regions, not just points; the index in PostGIS and most spatial databases

Spatial graphs: scene graphs

Where coordinates are unknown or unimportant, space can be stored as relations. A scene graph (Johnson et al. 2015) has objects as nodes and relations such as on, left_of, near as edges. 3D scene graphs (Armeni et al. 2019; Hydra, Hughes et al. 2022) stack layers — building → rooms → places → objects — giving robots both geometry and meaning. This is the most natural spatial form for an agent like MPCS.

07

Temporal data structures

Temporal data answers when. Time is one-dimensional, which helps, but it comes in two shapes — instants (an alarm sounded at step 42) and intervals (the pan was hot from step 40 to step 55) — and facts can stop being true.

7.1 Logs and time-ordered indexes

Events arrive in time order, so the simplest structure is an append-only log. A B+-tree keyed on time turns "what happened between t₁ and t₂" into a range scan. Time-series databases partition data into time chunks (per hour, per day) so old chunks can be compressed or dropped wholesale; many use log-structured merge trees (O'Neil et al. 1996), which make writes cheap.

7.2 Intervals

An interval tree (Edelsbrunner 1980; Cormen et al.) stores intervals so "which intervals contain time t" or "overlap [a, b]" run in O(log n + answers). Allen's interval algebra (Allen 1983) defines the thirteen possible relations between two intervals — before, meets, overlaps, during, starts, finishes, equals and their inverses — the vocabulary for reasoning like "the smell started before the alarm and overlapped it".

7.3 Two clocks: bitemporal data

Databases distinguish valid time (when a fact was true in the world) from transaction time (when the system learned it) (Snodgrass & Ahn 1985). Keeping both lets a system answer "what did I believe at step 50?" — essential when a later observation corrects an earlier one, as expert corrections do in MPCS.

7.4 Temporal knowledge graphs

A static triple becomes a quadruple (subject, predicate, object, time) or carries a validity interval. Models learn over them:

  • TTransE (Leblay & Chekol 2018) and HyTE (Dasgupta et al. 2018) — time-aware embeddings; HyTE projects each time step onto its own hyperplane.
  • Know-Evolve (Trivedi et al. 2017) and RE-NET (Jin et al. 2020) — treat facts as an event sequence and predict future events.
  • TGN (Rossi et al. 2020) — graph networks where each node keeps a memory updated by timestamped interactions.
  • Zep / Graphiti (Rasmussen et al. 2025) — a bitemporal KG as long-term memory for LLM agents: edges are invalidated, not deleted, when contradicted.

7.5 Episodic memory streams

Tulving (1972) separated episodic memory (personal events at a time and place) from semantic memory (general facts). LLM agents copy this split. Generative Agents (Park et al. 2023) store an episodic memory stream and retrieve by a weighted sum of recency (exponential decay), importance (a rated score) and relevance (embedding similarity). MemGPT (Packer et al. 2023) pages memories between a small working context and a large archive, like an operating system.

08

Spatio-temporal data structures

Spatio-temporal data answers where, and when: a moving robot, a spreading fire, an object that was on the table and is now in the sink. It is harder than either alone because the spatial index goes stale as things move.

8.1 Three strategies for moving data

Time as a dimension
3D R-tree
Treat (x, y, t) as one space and index boxes in it (Theodoridis et al. 1996). Good for history; poor for "now".
Versions
MV3R-tree, HR-tree
Keep a spatial tree per moment, sharing unchanged nodes between versions (Tao & Papadias 2001). Fast "as of time t" queries.
Motion
TPR-tree
Store position and velocity; bounding boxes grow with time, so the tree answers "where will it be" without constant updates (Šaltenis et al. 2000).

Trajectories — sequences of (x, y, t) points — are indexed by segment (TB-tree, Pfoser et al. 2000) and compared by trajectory distances such as dynamic time warping. Time geography (Hägerstrand 1970) gives the conceptual picture: each life is a path through a space-time cube.

8.2 Spatio-temporal graphs

  • Fixed nodes, changing signals — sensors on a road network; STGCN (Yu et al. 2018) combines graph convolution over space with convolution over time for traffic forecasting.
  • Changing nodes and edges — dynamic scene graphs where objects appear, move and change state; the 3D scene graph line of work (Rosinol et al. 2020, "3D Dynamic Scene Graphs") adds agents and time to Hydra-style layers.
  • Event graphs — nodes are events located in space and time; edges are temporal order, causality and co-location. This is the closest form to an episodic agent memory.

Where MPCS fits

MPCS memory is an episodic event store: each node is one experience — what was sensed, what was done, and the reward. The table maps each MPCS structure to its public counterpart.

Verdict

MPCS today is temporal-episodic with sensory content. It orders and links events in time, but has no place, no intervals and no activation. Space enters only indirectly, through sensory features such as motion or distance cues. It is not yet spatio-temporal.

11

Proposal: a spatio-temporal MPCS

Each step borrows a proven structure and can be added without breaking the current pipeline.

Add place and identity to percepts

Optional location (a coarse cell or a named place such as kitchen/stove) and object_id. Use hierarchical cell IDs (quadtree or H3-style) so "same place" works at several scales.

percept.where = "kitchen/stove" cell = quadtree_id(x, y, level=3)

Place as a third partition key

Next to HMGI's modality partitions: an inverted index cell → episodes. Queries can then prefer memories from the same or neighbouring places, like an R-tree range query at our scale.

Spatial edges in the episode graph

Add same_place_prev and scene relations (on, near) alongside the time, action and object edges. The episode graph becomes a small dynamic scene/event graph.

Intervals and bitemporal facts

States that persist ("the pan is hot") get valid_from / valid_to; corrections close an interval rather than overwrite (as in Zep/Graphiti). Allen relations become available to KERL's explanation.

Spreading activation over the graph

Seed with SHMF similarity, scale by affect/importance, propagate with per-hop and recency decay, prune below a threshold (Collins & Loftus; HippoRAG). This also delivers the planned HMGI activation-and-pruning task and gives an anytime latency budget a natural visiting order.

Scale path

Beyond ~10⁵ episodes, add an ANN index (HNSW) over percept embeddings for seeding, keeping the symbolic hard filter in front of it.
