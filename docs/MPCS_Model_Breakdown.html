MPCS · Model Breakdown

Baseline to SHMF

What each memory model is made of, how it performs, and what each step improved.
3 Oct 2026 Code: Model/experimental/01–06, comparison/ Later models: MPCS Progress Report
Summary

This report compares four stages of the MPCS memory: the baseline (feature counting, gated by Bloom filters, with Z-numbers; plus the four-sense Core v2 engine), HyST (hard/soft filtering), HMGI (modality-partitioned indexing) and SHMF (HMGI and HyST combined).

On fresh scenes from the 700-memory bank, the original two-sense baseline scores 43.1%, HyST 64.0% and SHMF 75.6%, with unsafe decisions falling from 47.1% to 2.1%. HMGI makes the same decisions as Core v2 and contributes structure rather than accuracy.

To compare like with like, we also built Baseline v2: the same baseline algorithm, given the same four-sense inputs and five actions as the newer models. It scores 79.6% / 73.3% (clean / noisy) on v3 — above SHMF — but only 52% on the hand-written v2 bank, where HyST and SHMF reach 100%. Most of the old baseline's deficit came from its two-sense inputs, and HyST/SHMF still carry Core v2's per-action voting. A quick test of SHMF's filter with the baseline's global vote scores 80.4% / 74.2%, the best of all.

01

Purpose of the work

MPCS is a cognitive agent that perceives a scene through up to four senses — vision, audio, touch, smell — and chooses one of five actions: approach, observe, alert, ignore, withdraw. Instead of a fixed rulebook, it decides by recalling past experiences: which similar scenes it has met, what it did, and how that turned out.

The goal of this line of work is to make that recall correct, safe and fast:

  • Correct — recall the experiences that actually bear on the current scene.
  • Safe — never let an irrelevant memory talk the agent into approaching something dangerous.
  • Fast — keep recall cheap as memory grows step after step.

The plan (the Perceptual Memory Indexing gameplan) took three published ideas — HyST, HMGI and KERL — and adapted them to MPCS one at a time, measuring each against everything before it. This report covers the first stretch: from the baseline to SHMF.

02

Concepts from the ground up

Case-based reasoning

The core loop: find past scenes like this one, and do what worked there. Everything else is detail on two questions — what counts as "like this one", and how to combine memories that disagree.

Percepts and memories

A percept is a set of discrete features grouped by sense. A memory stores a percept, the action taken, the reward (−1 to +1) and the step it happened at.

vision: {object_type: pan, color: grey} touch: {thermal: hot} # memory: this percept, action=withdraw, reward=+0.9, step=412

Similarity

The simplest similarity counts matching features. A better one weights each feature by how sure we are we perceived it.

Z-numbers

A Z-number pairs a value with a confidence: (hot, 0.9). Similarity then credits each matching feature by the lower of the two confidences, divided by the query's total confidence, so an exact repeat scores 1 and a faintly perceived match counts for less.

sim(q, m) = Σmatching min(cq, cm) / Σq cq

From memories to a decision

For each action, gather the most similar memories where that action was taken and average their rewards, weighted by similarity and recency. The best-supported action wins; if no memory supports any action, the agent observes. Novelty (one minus the best similarity) says how unfamiliar the scene is.

Bloom filters

A compact bit array that answers "have I seen exactly this before?" with no false negatives and a small chance of false positives. A d-left counting variant also supports deletion. Fast, but it only knows exact matches.

Hard and soft constraints

Some features decide whether the rest of the comparison matters at all. A hot pan and a cool pan share most features, but temperature is decisive. A hard constraint must match; a soft one is scored by closeness. The MPCS reflex rules (hot surface → withdraw, alarm → alert) tell us which features are safety-critical.

Indexing and partitioning

An index lets a query skip records that cannot be relevant. Partitioning groups records by a key (here, which senses they carry), so a query only scans the groups that could match.

Episode graph

Memories linked as a graph: each one connects to the previous step, the previous time the same action was taken, and the previous time the same object was seen. This captures sequence and context that a flat list loses.

04

Baseline models

"Baseline" here is the family of models that existed before the gameplan work. All four use the same idea: score every memory by similarity and vote.

G1 · Basic
Feature counting
Vision + audio, four actions (no withdraw). Similarity = number of equal features. Global top-5 vote.
G2 · Bloom
Bloom-gated
G1, but memory is only consulted if a Bloom filter says the exact scene was seen before.
G3 · Z + dlCBF
Z-numbers, d-left counting BF
Z-number summaries and a deletable Bloom filter as the gate. Confidence fixed at 1.0. 01_baseline_z.
G4 · Core v2
Four-sense engine
All four senses, five actions, per-sense confidence, reflexes, ageing, expert memories. Top-5 per action. 02_core.

How they performed

  • The Bloom gates never improved a decision. When open, G2 and G3 decide exactly like G1; when closed, they retrieve nothing. On v3 fresh scenes accuracy drops from 43.1% (G1) to 38.1%, and unsafe rises from 47% to 62%.
  • Z-numbers at confidence 1.0 equal plain counting — G3's outputs match G2's everywhere.
  • The two-sense schema cannot see danger. Without touch or smell, and without withdraw, 25–29% of v3 answers are inexpressible for G1–G3.
  • Core v2 adds senses but loses accuracy (34.2% on v3 clean). Each action gets its own top-5 memories, and a reward average ignores how similar those five are, so loosely related memories can outvote an exact match.
The lesson

The problem was not how similarity was computed, but who was allowed to vote. More senses gave the model more ways to find loosely related memories.

Baseline v2 — the baseline on matching inputs

G1–G3 cannot be compared fairly with the newer models because they never see touch or smell and cannot answer withdraw. Baseline v2 (01_baseline_z/baseline_v2.py) keeps G1's algorithm exactly and gives it the newer models' inputs:

InputFour senses, partial percepts allowed, v3 bankYes — identical percepts and memories

DecisionBest evidenced action; observe if noneYes — the shared engine rule
Gate (variant)Baseline v2+dlCBF: consult memory only if the exact scene was seenThe G2/G3 idea
  • On v3 it is strong: 79.6% clean, 73.3% noisy, unsafe 0.0% / 1.2% — above HyST and SHMF. The generated scenes cluster tightly around 16 scenario types, so the five nearest memories nearly always share the right action.
  • On the hand-written banks it is weak: 51.7% on v1 and 52.4% on v2, against 79–100% for HyST and SHMF. There, near neighbours often differ on exactly the feature that matters, and plain counting cannot tell.
  • The gate still hurts: on v3 clean the dlCBF shuts for 62% of queries and accuracy falls to 45.6%. Its 0% unsafe rate is only because it observes whenever the gate is shut.
What this reveals

Core v2's weakness was its per-action top-5, not its senses or confidences — and HyST and SHMF inherit that per-action vote inside their filtered sets. Replacing it with the baseline's global top-5 inside SHMF's filter gave 80.4% / 74.2% with 1.7% / 2.1% unsafe in a one-off test: better than either alone.

05

HyST — hard filters, soft residual

HyST

Hybrid Structured–Textual retrieval

04_hyst · adapted from the gameplan's hybrid-retrieval paper
Some features must match exactly; the rest are scored softly.

What it consists of

  • Hard slots, derived automatically from the reflex rules (any feature a reflex tests is safety-critical). A memory is eligible only if every hard slot matches the query.
  • Soft kernel: a graded ordinal score on the remaining features, so medium is closer to high than low is.
  • Divergent switch (exploration): hard mismatches are discounted (×0.6) instead of excluded, so the agent can reason by analogy.
  • Urgent flag (convergent only): the hard filter is absolute and exploration is off.

Result

The biggest single jump in the project: v3 fresh-scene accuracy 34.2% → 64.0%, unsafe 31% → 1.2%, and 100% on both hand-written v2 sets. Weakness: on unfamiliar scenes the strict filter often admits nothing (18% of clean, 41% of noisy queries), and the agent can only observe.

06

HMGI — partitioned memory

HMGI

Hybrid Multimodal Graph Index

05_hmgi · adapted from the gameplan's multimodal-index paper; structural part only, no approximate-nearest-neighbour index
Index memories by which senses they carry, and link them into episodes.

What it consists of

  • Modality partitions: memories bucketed by sense; a query scans only buckets sharing a sense with it.
  • Episode graph: links to the previous step, the last same-action memory and the last same-object memory.
  • Scan instrumentation: records how many memories each query touches.

Result

Decisions are identical to Core v2's by construction (same scoring, fewer records looked at). It scans 637–671 of 700 memories instead of all 700, but is no faster at this size: building the candidate list costs about what it saves. Its value is structural — the partitions and graph that SHMF and the later models build on.

07

SHMF — the combination

SHMF

Smart Hybrid-Modality Filtering

06_shmf · our combination of HMGI and HyST
Partition first, filter hard/soft second, relax only when nothing survives.

Partition (HMGI)

Narrow memory to records that share a sense with the query.

Strict filter (HyST)

Remove records that disagree on safety features. Novelty is measured here, so the agent still knows when a scene is new.

Auto-relax

If nothing survives, retry in divergent mode, dropping zero-similarity records. Never under the urgent flag.

Score and decide

Soft-kernel scoring, best evidenced action, one cached pass per step.

Result

Auto-relax cuts empty results from 18% / 41% to 2.3% / 4.8%. Accuracy rises to 75.6% clean and 68.1% noisy, with unsafe decisions at 2.1% / 3.8%. SHMF keeps HyST's safety while fixing its silence.

What the examples show

HMGI always answers like Core v2. HyST and SHMF fix Core v2's unsafe approach on danger scenes, and SHMF answers where HyST's strict filter is empty. Baseline v2 wins when the nearest neighbours agree, and loses when a decisive cue (smoke rather than heat) is outvoted by look-alike scenes — the case HyST's hard filter exists for. The dlCBF gate silences the model on any scene not stored verbatim.

Fixes found along the way

Comparing all models side by side exposed two bugs in the shared engine, now fixed in every model from Core v2 on:

  • Similarity kernel — matched features were scored c1 × c2, so an exact repeat scored 0.96 instead of 1. Now min(c1, c2).
  • Empty evidence — with nothing retrieved, every action tied at 0.5 and the tie went to ignore. Now the agent observes. HyST's unsafe rate fell from 22.9% to 1.2%, SHMF's from 5.4% to 2.1%.

Data grew alongside

Each bank was built when the previous one stopped separating the models: v1 could not show the value of touch and smell, so v2 added them; v2 was small and clean, so v3 added scale, partial percepts, contradictions and expert corrections — the conditions under which HyST's filter and SHMF's relaxation actually matter.

11

What we take forward

  • Compare on matching inputs. Given the same senses and actions, the old baseline algorithm beats HyST and SHMF on the generated bank. Much of the apparent progress from G1 came from richer inputs, not better retrieval.
  • Who votes and how they vote both matter. HyST's hard filter removes dangerous look-alikes, which is decisive on the hand-written banks. The baseline's global top-5 avoids per-action averaging, which is decisive on v3. Combining the two is the best result so far (80.4% / 74.2%).
  • Exact-membership structures do not suit similarity recall. The Bloom gates only removed evidence; they survive only as an exact-repeat hint.
  • Strictness needs a fallback. SHMF's relaxation recovers most of what strict filtering loses, while never relaxing under urgency.
  • Next step: make "SHMF filter + global top-k vote" a proper model, and re-check KERL and TIDE, which inherit the per-action vote too.
  • Structure pays off later. HMGI did not change accuracy or speed, but its partitions and episode graph underpin the later KERL and TIDE models, which add affect, explanation, spreading activation and time-bounded decisions (see the MPCS Progress Report).
